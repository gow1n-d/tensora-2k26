# 1. Executive Direction

# 28. Rules & Regulations

The 2025 public FAQ/rules content covers participation, team size, registration, mandatory AI and submission requirements.

For 2026, these should become a formal rules section.

## Rule 01 — Eligibility

Only eligible students with valid institutional details may participate.

## Rule 02 — Team size

Teams must contain 2–4 registered members.

## Rule 03 — One-team policy

A participant may not belong to multiple teams.

## Rule 04 — AI requirement

Every project must contain meaningful AI/ML implementation.

Permitted examples:

- Machine Learning
- Deep Learning
- NLP
- Computer Vision
- Generative AI
- LLMs
- Reinforcement Learning
- Multimodal AI
- AI-assisted optimization

## Rule 05 — Development period

Core solution development must occur within the official hackathon window.

## Rule 06 — Pre-existing code

Third-party libraries and frameworks are permitted.

Pre-existing proprietary project code must not constitute the primary solution.

Teams must disclose significant pre-existing components.

## Rule 07 — Open-source usage

Open-source packages may be used according to their licenses.

## Rule 08 — Plagiarism

Copying another team's solution, submission or proprietary implementation results in disqualification.

## Rule 09 — AI-generated code

AI coding assistants may be permitted, but teams remain fully responsible for:

- correctness
- licensing
- security
- originality
- understanding of submitted code

## Rule 10 — Submission

Each team must submit:

- GitHub repository
- README
- demo video
- presentation
- technical report
- deployed/demo link where applicable

## Rule 11 — Repository

The repository must be accessible to judges during evaluation.

## Rule 12 — Demo

The demo must represent the actual submitted solution.

## Rule 13 — Presentation

Teams must comply with the allotted presentation time.

## Rule 14 — Conduct

Participants must treat organizers, judges, mentors and other teams respectfully.

## Rule 15 — Disqualification

Grounds may include:

- plagiarism
- fraudulent registration
- impersonation
- harassment
- malicious activity
- submission after deadline without approved extension
- deliberate disruption
- falsified results
- unauthorized access to other teams' systems
- violation of applicable law

# 46. Accessibility Requirements

## Images

Every meaningful image must have descriptive alt text.

Examples:

`TENSORA 2026 hackathon logo`

`Students presenting an AI prototype during the TENSORA finale`

`alt=""`

## Navigation

Use semantic labels:

`Main navigation`

`Primary registration`

`Challenge navigation`

`Frequently asked questions`

## Color

Normal text should target at least WCAG AA contrast.

Do not use purple text on dark purple backgrounds merely because it matches the brand.

## Keyboard

All:

- buttons
- accordions
- modals
- links
- forms

must be keyboard accessible.

## Screen readers

Countdown should expose an accessible static equivalent, for example:

`Hackathon begins in 2 days, 4 hours.`

Do not make the visual timer the only source of deadline information.
